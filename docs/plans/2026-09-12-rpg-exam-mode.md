# RPG 備考模式：研途冒險

日期：2026-09-12。狀態：規劃完成，尚未實作。依據：使用者提供的七張 SQL Quest 圖片，以及本 checkout 的路由、課程、題型政策與儲存程式。本文是此功能的規格與進度來源。

## 1. 產品定位與邊界

新增可自由進出的「RPG 冒險」模式：把今天要學的觀念變成探索、把主動作答變成戰鬥、把錯題複習變成營火修復、把跨觀念解題變成 Boss 試煉。

現有今日學習、備考計畫、閃卡、題庫、模擬考、錯題本等模式維持原本行為、網址與紀錄。只新增入口；進入 RPG 不改成全站預設，也不把既有進度重新換算成遊戲等級。

主要目標是降低開始讀書的阻力，讓玩家知道「今天練什麼、卡在哪裡、下一步做什麼」。遊戲等級代表投入；考試能力另以無提示作答、延後回想與陌生題表現呈現。所有門檻與獎勵數字都是初版設計值，需試玩調整，並非已驗證的學習效果。

## 2. 從參考圖轉換成備考設計

| 參考圖 | 研途冒險 | 實際學習用途 |
| --- | --- | --- |
| 世界地圖與 NPC | 科目大陸、主題據點、今日出征 | 把備考範圍與下一步視覺化 |
| 冒險手冊 | 任務簿 | 依科目、觀念、題型、熟練狀態找題 |
| 記憶營火 | 營火複習 | 到期回想、錯題再戰、看提示後重新嘗試 |
| 面試公會 | 考場試煉／申論公會 | 混合觀念、限時練習、解題表達 |
| 工程實驗室 | 解題工坊 | 推演演算法、計算統計、拆解申論；可執行 SQL 後續擴充 |
| 技能樹 | 觀念技能樹 | 區分看過、輔助完成、獨立完成、延後回想、變式驗證 |
| 寫 SQL 打怪 | 作答戰鬥 | 正確作答推進戰況；保留題目原文、公式與圖表 |

採用深色底、暖金重點、像素地圖與怪物的方向，但自行設計素材與劇情。中文正文使用清楚易讀的字體，像素字只用於少量數字或標籤。

## 3. 世界與主題

故事設定：知識群島上的典籍散落，玩家透過理解觀念、解除錯誤推理與完成試煉修復據點。每段劇情以一至三句為原則，可略過；進入後直接提供「繼續上次任務」。

| 考試路線 | 地區 | 科目與任務示例 |
| --- | --- | --- |
| 資管 | 機巧群島 | 計概：SQL 港口、交易金庫、網路驛站、程序城、資料結構森林、AI 研究塔 |
| 資管 | 策略議會 | MIS：用五力分析、ERP／CRM／SCM、數位轉型案例提出建議 |
| 資管 | 機率星塔 | 統計：辨認分布、選擇方法、計算、解讀結果 |
| 資管／資工 | 語文遺跡 | 英文：詞義回想、句子理解、閱讀推論；題庫依考試分開 |
| 資工 | 邏輯聖殿 | 數學：線性代數、離散數學、證明與反例 |
| 資工 | 系統要塞 | 計結與 OS：快取、管線、排程與記憶體 |
| 資工 | 演算法森林 | 資結與演算法：追蹤步驟、複雜度、正確性與手寫解法 |

所有科目都有既有科目頁、主題與題庫／考古題資料，因此 RPG 從規劃起就涵蓋全部科目。以下是本次直接統計的資料量，不代表答案已全部覆核或可自動判分：

| --- | ---: | ---: |
| 資管英文 | 500 | 10 |
| 計概 | 260 | 10 |
| MIS | 37 | 10 |
| 統計 | 5 | 10 |
| 資工英文 | 400 | 8 |
| 數學 | 76 | 8 |
| 計結與 OS | 88 | 8 |

RPG 題库任務可直接引用各科現有資料，再按可靠性與判分政策選擇客觀戰鬥、自評工坊或閱讀任務。完整敘事章節另外標記開發狀態。`learning-catalog.ts` 只註冊計概，僅代表「短講義＋例題＋概念卡」這條課程路徑的接入範圍，不能解讀為其他科目沒有學習內容。科目已存在與 RPG 章節已完成是兩個不同狀態。

產業專題改為跨科支線，例如金融金庫（交易、資安、風險）、電商城鎮（SQL、推薦、CRM）、製造工坊（排程、IoT、品質統計）。職務專題轉為可切換的角色任務：分析師重視推論與解釋、工程師重視執行流程與除錯、策略顧問重視申論架構與取捨。角色只影響任務推薦和外觀，不增加答題數值，也不鎖科目。每個專題必須映射考點；未映射的趣味內容不計入備考覆蓋率。

## 4. 每日遊玩循環

預設一場 20 分鐘，可選 10／20／40 分鐘，隨時存檔退出。

1. **營火暖身，3 分鐘：** 回想兩個到期觀念。沒有到期內容時改成已學觀念暖身。
2. **探索新據點，5 分鐘：** NPC 提供一個情境，玩家先預測，再看短講義、例題與比喻的適用界線。
3. **戰鬥練習，8 分鐘：** 完成三至五個題目或解題步驟，可求提示。答錯後指出問題並安排重試。
4. **戰報與存檔，4 分鐘：** 列出獨立完成、靠提示完成、待複習觀念，選定下次回訪任務。

推薦順序：未完成的短任務 → 到期複習 → 最近錯誤的先備觀念 → 目前章節下一關。到期題過多時按時間預算取部分，不要求清空才能學新內容；允許玩家自行選擇主線。接近使用者設定的考試日，逐步提高混合題與試煉比例。

## 5. 戰鬥不是只換一層皮

每場戰鬥都綁定可說明的學習目標。怪物的招式就是常見誤解，玩家要識別與修正它。

- **小怪：** 單一觀念辨識或一步計算，約一至三分鐘。
- **精英：** 兩個觀念組合、除錯或解釋錯誤選項，約五至八分鐘。
- **Boss：** 三個階段，依序做觀念判斷、應用、陌生情境遷移。必須保留一部分未在該任務教學中揭露答案的題目。
- **營火再戰：** 遮住答案，重新回想；看完解析不直接算熟練。

客觀題正確時扣除怪物一個階段的 HP；答錯則顯示該誤解的反擊與解析入口。玩家不設會耗盡的體力，也不因答錯失去既得 XP。連續答錯兩次，提供「看示例／回先備觀念／繼續試」；不強制離場。

提示採三級：概念線索 → 解題步驟 → 完整解析。記錄用到哪一級；看過提示後完成，標為「輔助完成」。再次獨立作答與隔日回訪才能提升能力證據。

題型處理：

| 題型 | 互動方式 | 能力判定 |
| --- | --- | --- |
| 有可靠解答的選擇題 | 選答案、提交、解析 | 沿用現有題型與答案政策，提交前不洩漏解答 |
| 計算題 | 填結果與步驟 | 只有具備核對器、單位與容許誤差規格的題才自動判分，其餘自評 |
| 申論／證明／手寫程式 | 自行輸入，再對照評分規準 | 標示自評完成；不把 AI 或自評結果寫成客觀正確率 |
| 開放式推演 | 追蹤流程、解釋理由 | 首版可採文字與規準；互動模擬器後續做 |
| 有爭議或缺解答的題 | 閱讀、討論 | 不用於自動戰鬥通關、技能認證或計分 Boss |

申論 Boss 可以完成「提交答案 → 對照規準 → 修訂」流程並取得參與獎勵，但戰報顯示「自評完成，待驗證」，不冒充已客觀通關。

## 6. 成長與複習

初版獎勵：完成首次教學互動 10 XP、首次有效解題 20 XP、到期回想完成 10 XP、章節流程完成 50 XP。相同任務版本的首次獎勵只能領一次；同一觀念同一天複習獎勵最多一次。重試仍可練習，不能靠重新整理或重複提交領取。裝備只解鎖外觀、稱號與營地裝飾，不提供正確率或跳題加成。

技能狀態保留證據類型與日期：

1. 已探索：完成教學互動。
2. 輔助完成：使用提示或解析完成。
3. 獨立完成：無提示完成合格題目。
4. 延後回想：至少隔一個日曆日後，無提示再次完成。
5. 變式驗證：無提示完成不同題目或已審核變式。

自評與客觀結果分開展示；沒有足夠題目時標示「待補驗證題」，不以同題連刷補足變式條件。逾期顯示「待回訪」，不刪除成就。XP、地圖進度、技能證據與試煉分數各自呈現，不輸出錄取機率。

首版 RPG 營火使用自己的觀念卡排程，可重用 `src/lib/srs.ts` 的純計算邏輯，但不讀寫舊閃卡排程作為副作用。既有模式與 RPG 學習記錄暫時各自保存；跨模式聚合列為後續明確設計，避免雙重計分或意外改掉到期日期。

## 7. 第一個可玩章節：交易金庫

建議以現有 `lesson-im-it-db-transactions-01` 示範完整玩法，以「公會金庫轉帳後發生斷電」串起 ACID、並行風險與復原。這是可玩切片的選擇，不是把 RPG 限定為計概；所有科目的任務入口同步納入 MVP。以下情境為新編教學草案，需要內容覆核後才上線。

| 節點 | 劇情與學習動作 | 完成條件 |
| --- | --- | --- |
| 金庫入口 | NPC 問：扣款成功、入帳前斷電怎麼辦？先預測再讀例題 | 完成教學互動，標記探索 |
| 半筆轉帳怪 | 分辨 atomicity 與 durability | 合格客觀題無提示完成，或標記輔助完成 |
| 雙重提款怪 | 追蹤兩筆交易的讀寫，找出並行風險 | 作答後說明錯誤發生在哪一步；開放答案保留自評標記 |
| 守庫者 Boss | ACID 辨識 → 故障情境 → 不同題目的應用 | 依每題政策產出客觀／自評分開的戰報 |
| 營火 | 次日重新回想較弱的觀念 | 記錄延後回想證據 |

現有課程連到 `q-pp-im-it-107-7` 等考古題；實作時須逐一查 `getQuestionPracticePolicy`，不能因有課程連結就假設可自動判分。Boss 題先保留，不能先在教學任務中展示答案。若合格題不足，縮小驗證範圍或補審核原創題，不灌入爭議題。

先做一條可完整走完的路：教學、兩場練習、一場分階段 Boss、次日複習。通過後再加入既有 `lesson-im-it-db-sql-querying`，不把可執行 SQL 引擎列為首版必要條件。

## 8. 畫面與導覽

新增 `/{exam}/rpg` 作為入口，原有 header 僅增加「RPG 冒險」連結。RPG 內有自己的地圖、任務、營火、技能四個主要分頁，以及明確的「返回一般備考」。

桌面世界地圖：左側角色與導覽、中央可點節點地圖、右侧目前任務與建議時間。桌面戰鬥：上方短場景與敵人階段，主要空間留給題幹、作答與解析。手機改成直向卡片，題目優先，地圖可切清單；不要求 WASD、拖曳或精確點擊像素座標才能玩。

所有互動有鍵盤路徑與文字狀態，狀態不只靠顏色。提供減少動態選項、動畫略過、音效預設關閉；題目與解析字級不隨像素畫風縮小。首版不需要自由走動、即時物理、多人連線或大型遊戲引擎。

## 9. 技術接入與資料契約（提案）

本次只寫規劃。以下路徑尚未建立。

- 路由：`src/app/[exam]/rpg/` 下配置地圖、`quests/[questId]`、`camp`、`skills`。
- UI：`src/components/rpg/`；顏色與動態只作用於 RPG 容器，避免改動全域 theme 和原頁面排版。
- 邏輯：`src/lib/rpg/` 管理任務選擇、題型轉接、戰鬥狀態機、技能證據、獎勵去重。
- 內容：`public/data/rpg/` 保存章節與任務 manifest，參照原有 lesson／question／concept ID，不複製題幹答案。
- 儲存：獨立 RPG store 與版本化 localStorage key，按 exam 分區；首版明示「儲存於此瀏覽器」，含匯出／匯入與只清除 RPG 存檔的操作。D1 與跨裝置同步另列後續階段。

既有 `content.ts` 匯入兩條考試路線的全部科目與共用題庫，是全科 RPG 任務來源。`learning-catalog.ts` 目前只註冊 `imItLearningCatalog`，作為額外的結構化講義來源；資工計結雖有工作目錄中的內容檔，不能據此視為已接入此課程入口。`learning.ts` 的 lesson／card／source 與 `learningScenario` 可供新模式讀取。新模式先檢查 `content.ts` 的考卷可靠性，再透過 `question-practice-policy.ts` 取得 `auto / self_review / read_only`，不自行放寬資格。

整合盤點確認：既有 practice stats／review API 跨 mode 統計，不能直接向原 API 寫入 `mode=rpg`；原題目頁元件也可能內建寫入。RPG 作答必須使用獨立提交介面。原 `recordTaskEvidence` 會更新一般任務完成度，原 flashcard store 會改共用 SRS，均不可直接當 RPG 結算操作。細節見 `.work/rpg-integration-audit.md`。

最小資料契約：

| 實體 | 必要欄位 |
| --- | --- |
| Region | id、examId、subjectId、title、contentStatus、questIds |
| Quest | id、version、regionId、conceptIds、lessonRefs、questionRefs、prerequisites、estimatedMinutes、objective、hintRefs、rewardRule |
| Attempt | id、sessionId、questId、questVersion、questionId、contentVersion、answer、gradingMode、result、hintLevel、revealedAnswer、startedAt、submittedAt |
| SkillEvidence | conceptId、attemptId、evidenceType、verificationType、recordedAt |
| Save | schemaVersion、examId、activeSession、attempts、claimedRewardKeys、reviewStates、preferences |

提交後以 attempt ID 與獎勵 key 去重，結果、技能證據與獎勵作為同一存檔更新。存檔失敗必須提示且保留當前答案；不能先顯示已保存。載入要校驗版本；不相容資料保留匯出能力，不靜默清空。內容移除或答案修正時保留歷史紀錄，但相關技能標為待重驗；跨科不能因題目 ID 撞名串到其他角色。

目前 root layout 固定渲染 Header 與 container。首版 RPG 在現有容器內建立場景，不為滿版效果重構其他頁面 layout。開始寫 Next.js 程式前依 AGENTS 要求閱讀安裝版本的本地 docs；本規劃不假設額外框架 API。

## 10. 階段與驗收

| 階段 | 交付 | 通過條件 |
| --- | --- | --- |
| A：內容切片 | 交易金庫 manifest、怪物誤解、提示、Boss 題分配 | 每任務對應考點、來源與判分政策；無死路或未達先備條件仍被強制推薦 |
| B：可玩 MVP | 全科入口與合格題庫任務、交易金庫示範章、營火、技能、存檔 | 全科依題型提供練習，示範章能完成整場循環並中途重開續玩；鍵盤與手機可用 |
| C：內容擴充 | SQL、網路、OS 等已接入課程；補變式題 | 題目逐一通過內容與政策驗證，不因數量目標放寬審核 |
| D：全科深度章節與專題 | 英文、MIS、統計、資工完整故事章、產業支線、進階解題工坊 | 在已存在的全科任務上補齊講義、故事與各題型規準，逐章驗收 |
| E：延伸 | 跨裝置同步、跨模式能力彙總、SQL 執行器 | 各自有資料契約、去重與失敗處理，再接現有系統 |

MVP 必須驗證：

- 原有 URL、題型政策、複習排程、模擬考與紀錄流程維持；RPG 操作不改寫舊儲存 key 或呼叫舊練習寫入 API。
- 無提示／提示／揭答案／自評／爭議題產生不同結果；爭議題不能獲客觀通關。
- 刷新、返回上一頁、連按提交不重複領獎；跨日、切考試、版本更新、存檔故障有明確行為。
- 一次通關不直接取得延後回想或變式驗證；同題重試不算陌生題。
- 內容 validator 檢查 ID、題目資格、先備循環、Boss 保留題與空題池。
- 執行當前專案 lint、typecheck、相關 Jest 與 build；實際試玩手機、鍵盤、減少動態及中途續玩。記錄既存工作樹問題與本次新增問題。

試玩觀察：能否迅速開始第一題、遊戲操作是否打斷思考、是否理解錯誤原因、隔日是否能回想、是否能解不同題。單看停留時間、連續天數或 XP 不能當成學習成效。
